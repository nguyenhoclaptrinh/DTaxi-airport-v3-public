# Airport Data Model Specification

## 1. Mục tiêu

Airport Data Model định nghĩa cấu trúc dữ liệu dùng để mô tả hình học và topology của khu vực hoạt động trên mặt đất của sân bay phục vụ mô phỏng di chuyển máy bay.

Mô hình dữ liệu phải cho phép:

- biểu diễn runway, taxiway, apron
- xác định các điểm giao (intersection)
- xác định đường di chuyển hợp lệ của máy bay
- hỗ trợ thuật toán tìm đường taxi
- hỗ trợ hiển thị bản đồ sân bay
- hỗ trợ phát hiện xung đột đường lăn

Mô hình được xây dựng theo dạng **graph topology**.

---

# 2. Các thành phần dữ liệu chính

Airport Surface Model bao gồm các thực thể sau:

- Airport
- Runway
- Taxiway
- Stand
- Holding Position
- Node
- Edge
- Route

---

# 3. Airport

Airport là thực thể gốc chứa toàn bộ cấu trúc dữ liệu sân bay.

## Thuộc tính
Airport
{
airport_id: string
airport_name: string
icao_code: string
elevation_ft: number
runways: Runway[]
taxiways: Taxiway[]
stands: Stand[]

nodes: Node[]
edges: Edge[]
}

---

# 4. Runway

Runway mô tả đường băng dùng cho cất cánh và hạ cánh.

## Thuộc tính
Runway
{
runway_id: string
designation: string
length_m: number
width_m: number

surface_type: string

threshold_start_node: NodeID
threshold_end_node: NodeID

holding_positions: HoldingPosition[]
}


designation tuân theo chuẩn ICAO runway numbering.

Ví dụ:
09
27
25L
25R

---

# 5. Taxiway

Taxiway mô tả đường lăn.

## Thuộc tính
Taxiway
{
taxiway_id: string
name: string

width_m: number
surface_type: string

edges: EdgeID[]

}

---

# 6. Stand (Gate)

Stand mô tả vị trí đỗ máy bay.

## Thuộc tính
Stand
{
stand_id: string
name: string

node_id: NodeID

allowed_aircraft_types: string[]

}


---

# 7. Holding Position

Holding Position là vị trí dừng trước runway hoặc khu vực hạn chế.

## Thuộc tính


HoldingPosition
{
holding_id: string

node_id: NodeID

associated_runway: RunwayID

type: string

}


type có thể bao gồm:


runway_holding
taxiway_holding
intersection_holding


---

# 8. Node

Node đại diện cho một điểm trong topology sân bay.

Node được sử dụng để:

- biểu diễn giao điểm taxiway
- biểu diễn điểm đầu cuối runway
- biểu diễn điểm vào runway
- biểu diễn vị trí stand

## Thuộc tính


Node
{
node_id: string

latitude: float
longitude: float

node_type: string

connected_edges: EdgeID[]

}


node_type có thể là:


runway_threshold
taxiway_intersection
holding_point
stand
taxiway_point


---

# 9. Edge

Edge biểu diễn một đoạn đường nối giữa hai node.

Edge là thành phần cơ bản của graph.

## Thuộc tính


Edge
{
edge_id: string

start_node: NodeID
end_node: NodeID

length_m: number

edge_type: string

taxiway_name: string

direction: string

}


edge_type có thể là:


taxiway
runway
service_road


direction có thể là:


bidirectional
forward
reverse


---

# 10. Graph Representation

Airport surface được biểu diễn dưới dạng graph:


G = (V, E)

V = tập Node
E = tập Edge


Trong đó:


Node = vị trí vật lý
Edge = đoạn đường taxi


Graph phải đảm bảo:

- tất cả taxiway phải liên thông
- runway phải kết nối với taxiway qua holding position

---

# 11. Route

Route mô tả đường taxi mà máy bay sẽ di chuyển.

## Thuộc tính


Route
{
route_id: string

aircraft_callsign: string

start_node: NodeID
end_node: NodeID

edges: EdgeID[]

}


---

# 12. Aircraft Position Representation

Vị trí máy bay được xác định bằng:


AircraftPosition
{
aircraft_id: string

edge_id: EdgeID

progress: float

}


progress ∈ [0,1]

Ý nghĩa:


0 = đầu edge
1 = cuối edge


---

# 13. Movement Constraint Rules

## 13.1 Runway Access

Máy bay chỉ được phép đi vào runway khi:


ATC clearance = true


và node tiếp theo thuộc runway.

---

## 13.2 Holding Position

Máy bay phải dừng tại holding position khi:


runway_clearance = false


---

## 13.3 Taxi Direction

Nếu edge có direction:


forward


máy bay chỉ được di chuyển:


start_node -> end_node


---

# 14. Conflict Detection

Hai máy bay được coi là xung đột nếu:


aircraft_A.edge == aircraft_B.edge


và


|progress_A - progress_B| < safety_distance


---

# 15. Airport Data File Format

Dữ liệu sân bay được lưu trong file JSON.

Cấu trúc tổng thể:


AirportData
{
airport: Airport

nodes: Node[]

edges: Edge[]

runways: Runway[]

taxiways: Taxiway[]

stands: Stand[]

}

---

# 16. Yêu cầu dữ liệu

Dữ liệu sân bay phải thỏa mãn:

- mỗi edge phải có start_node và end_node hợp lệ
- node phải tồn tại trong danh sách node
- runway phải kết nối với taxiway thông qua holding position
- stand phải kết nối với taxiway network

---

# 17. Khả năng mở rộng

Mô hình dữ liệu phải cho phép bổ sung:

- service vehicle route
- deicing area
- maintenance area
- runway crossing point
- stop bar
- lighting system
